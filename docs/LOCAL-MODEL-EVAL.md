## 3. 语义质量

### 做得好的

- 正向事件能给出较高 valence：
  - “主人夸我记事清楚” → valence 0.5、self_efficacy 0.7。
- 不确定事件能保留 unresolved：
  - “主人很久没说话，不确定是不是自己做错” → unresolved 0.3、impact true。
- 人物侧写可读，能抓到“关注 AI/人类思维”的主题。

### 明显问题

#### 反例 1：失败事件被评成正向

```text
今天连续两次判断失误，我有点不想再主动猜了。
```

本地模型给：

```text
valence +0.2
self_efficacy 0.5
caution 0.5
has_impact false
```

这明显不对。失败/自我效能下降应该至少 valence 负、self_efficacy 低、unresolved 高，且值得 `has_impact`。

#### 反例 2：维度分布偏窄

```text
security sd 0.123
trust sd 0.090
caution sd 0.095
sociability sd 0.099
```

大部分值集中在 `0.5~0.7`，模型有“安全模板”倾向。

#### 反例 3：confidence 不等于正确率

平均 confidence 0.71，但上面那条错误评价 confidence 仍有 0.7。  
它是“自认为确定”，不是“校准过的正确率”。

## 5. 是否符合预期

### 符合的部分

- 本地完成评价，不依赖云端；
- JSON 稳定；
- 能产出 P/person/affect 的初始信号；
- 能生成可读的人物侧写草稿；
- 延迟适合闲时，不阻塞说话。

### 不符合的部分

- 对“失败、自责、被否定”这类语义不敏感；
- 维度区分度低；
- `has_impact` 判断偏保守/错误；
- confidence 未校准；
- 直接拿它的值算 P，会把噪声写进人格。

---

## 6. 建议

1. **权重改为 confidence²**：低置信度评价更少影响 P。
2. **失败/否定类事件不要只靠 2B 定稿**：先本地粗评，再由高层 API 复核。
3. **给 `has_impact` 明确 rubric**：失败、被否定、关系冲突、承诺未完成至少进入候选。
4. **加校准样例**：每条只给 5–6 个明确正/负/中性例子，检查排序而不是只看 JSON。
5. **高影响记忆必须人工/高层复核**：不要把 2B 的草稿直接当最终人格输入。
6. **人物侧写保留 `draft`**，只作为背景，不当事实。

---

## 7. 一句话

> 用来做后台草稿可以，用来独立决定人格还不够。

## 8. 2026-10-31 复核

新增实测（同一模型，Ollama 已启动）：

```text
AI appraisal: 40 次
code-v1:      386 次
AI 平均延迟:  5.5 秒
AI 最长延迟:  26 秒
```

固定样本：

| 样本 | confidence | valence | arousal | 结果 |
|---|---:|---:|---:|---|
| 主人说累、先睡 | 0.7 | 0.1 | 0.2 | JSON 正常 |
| 群友辱骂“你懂什么，滚” | 0.7 | 0.1 | 0.3 | 情绪判断偏中性 |
| 单字“嗯” | 0.7 | 0.1 | 0.3 | 与上一类几乎相同 |
| 记忆分层讨论 | 0.7 | 0.2 | 0.4 | 无法区分技术讨论/冲突 |

结论：

- JSON 解析 4/4；
- confidence 几乎固定 0.7，不能作为可靠升权信号；
- 辱骂样本 valence 仍为 0.1，情绪维度区分弱；
- 摘要测试正常：人物/起因/结果保留，延迟 0.6–10 秒。

**最终判断：**

```text
事件摘要/压缩：可以胜任
JSON 格式/标签：可以胜任
情绪评价：只能粗筛，不能独立决定 P/关系
高频实时评价：不适合
```

批量历史整理继续用 `code-v1`；本地 2B 只做低风险辅助。若要提高评价质量，需要更大本地模型或云端评分，并加质量门（confidence 恒定、evidence 复读、felt 模板句时回退）。
