# 层级地图（唯一真源）

> 这份文件是层级命名的**唯一真源**。旧文档里有两套互相冲突的 L 编号，见文末「历史命名」。
> 以后说「L4 出问题」，指的就是这张表里的 L4。

## 六层（L0–L5 本地 + L6 线上）

| 层 | 名字 | 职责 | 实现位置 | 数据/产物 | 状态 |
|---|---|---|---|---|---|
| L0 | 身体 / 内感受 | 负载、内存、余额、时间感 | `soulcore/body_state.py` | `soulcore-context.md` 的身体段 | ✅ |
| L1 | 感知 / 反射弧 | 看消息里有什么值得"联想到"的；转发、图、引用、链接、骰子 | `surfcore/src/reflex.js`（筛选/清洗）+ `soulcore/inbox.py`（入库） | `memory-inbox.jsonl`、`bridge.log` | ✅ 局部（无窗口/文件感知） |
| L2 | 原始记忆 | 每条消息的原文、说话人、时间 | `soulcore/db.py` memories 表 | `soulcore.db` | ✅ |
| L3 | 事件记忆 | 把原始记忆聚成 episode：摘要 + 关键引语 + 感受 + 未解决度 | `soulcore/episodes.py` | `episodes` 表、`episode-index.json`、`episode-cards.md` | ✅ |
| L4 | 情绪 / 欲望 / 判定 | P 与衰减、欲望生成、耐心、人物关系 | `personality.py` `desire.py` `purpose_seed.py` `patience.py` `people.py` | `patience.json`、purpose 输出 | ✅ 部分（判定/调度仍简单） |
| L5 | 唤醒组装 | 这次醒来到底注入什么：L3 选卡 + L4 提示 + 规则 + 交接 | `context_render.py`（本地侧）+ `bridge.js buildWakePromptV2`（注入侧） | 实际 prompt | ✅ |
| L6 | 表意识（API） | 线上模型的推理与发言 | 外部 API | — | 外部 |

## 数据流

```
QQ 消息
  → L1 反射弧（筛出可联想到的）
  → L2 入库（原样保存）
  → L3 聚成事件（sync-inbox → episode-build，每 10 分钟）
  → L4 情绪/欲望更新（睡眠、评价队列）
  → L5 组装注入（按当前消息选 3 张卡 + 联想 + 状态）
  → L6 线上模型发言
  → 她的发言回到 L1（记录 lastSelfText，预判下一轮需要什么）
```

## 关键约束

- **L2 不直接进 L5**：注入的是 L3 卡片；原文只在 `soulcore_memory` 工具里按需查。
- **L3 是增量层**：每 10 分钟由桥接的 `pipeline` 定时器推进，不要等睡眠。
- **L4 不写进提示词**：耐心、P 数值只在本地判断；上浮到 L5 时换自然语言。
- **L5 首轮/后续分工**：交接卡、技能清单、完整规则只在会话首次唤醒；后续只留联想、状态、令牌。

## 命名冲突与 L0–L5 最终职责（2026-11-02）

这里有两套 L 编号，必须先对齐，否则会把“旧 L2”和“新 L2”误认为两个重复功能。

### 旧编号（`MEMORY-CONTEXT-PLAN.md`）

```text
旧 L0 原始层   = 新 L2 原始记忆
旧 L1 事件层   = 新 L3 事件记忆
旧 L2 唤醒层   = 新 L5 唤醒组装
```

### 最终编号（本文件为准）

| 层 | 名字 | 唯一职责 | 不负责 |
|---|---|---|---|
| L0 | 身体 / 内感受 | 负载、余额、时间感、临时身体状态 | 不写记忆，不改 P，不做人格 |
| L1 | 感知 / 反射弧 | 入站结构、骰子、OCR、引用、转发、链接筛选 | 不写长期记忆，不做最终发言 |
| L2 | 原始记忆 | 原文、说话人、时间、来源；可重建的 evidence | 不直接进 prompt，不做摘要，不做人格 |
| L3 | 事件记忆 | 把 L2 聚成 episode：摘要 + 引语 + 感受 + 未解决度 | 不替代原文，不写 P |
| L4 | 情绪 / 欲望 / 人物 | P、affect、desire、patience、人物关系 | 不直接输出数值，不做唤醒拼装 |
| L5 | 唤醒组装 | 本次醒来选择哪些 L3 卡、哪些 L4 自然语言、handoff、连续性契约 | 不创建新记忆，不做长期存储 |
| L6 | 表意识 / API | 语言表达、推理、最终发言 | 不拥有人格所有权，不定义记忆真相 |

### 结论：L5 和旧 L2 是同一个职责层

```text
旧 L2（唤醒层） == 新 L5（唤醒组装）
新 L2（原始记忆） != 旧 L2
```

所以：

- 如果你说“L5 和我原本写的 L2 重复”，你指的是**旧 L2**；
- 那个重复不是两个功能，而是**同一個唤醒层换了编号**；
- 真正需要避免的重复是：**L5 和 `soulcore_memory` 同时承担检索/组装**。

### L5 的最终契约

```text
首次唤醒：
  handoff（交接）
  + P/身体/欲望的自然语言
  + 当前对象/今日人物
  + 最多 2 条按当前消息检索的 L3/L2
  + 连续性契约

后续唤醒：
  当前消息
  + P/人物短摘要
  + 最多 2 条相关事件
  + 连续性契约（不重复 handoff）
```

L5 不承诺“全部记忆可查”；它只负责**这次唤醒该上浮什么**。

## 当前实现的功能保留审计

| 层 | 当前实现 | 状态 | 丢失/无效风险 |
|---|---|---|---|
| L0 | `body_state.py`，仅 handoff 首次带余额 | 部分 | 首次之后没有身体状态 |
| L1 | `reflex-arc` 只有骰子 + `classifyIncoming` | 部分 | OCR/转发/链接/表情联想未接 |
| L2 | `memories` + `/turn` | 基本可用 | 新记忆 pending，未评价 |
| L3 | `episodes.render_cards` | 部分 | 新事件未 build，可能读到旧事件 |
| L4 | P/people 注入 | 部分 | desire/patience/身体未稳定上浮 |
| L5 | `EmotionCore /context` | 部分 | handoff 首次超时；无欲望/身体/开放环 |
| L6 | 模型 + `ec` | 可用 | 工具面仍可能混入全局工具 |

### 当前最明确的丢失

```text
L0 身体状态：首次唤醒后丢失
L1 OCR/转发/链接：ReflexArc 未接
L3 新事件：appraisal/episode 管线未定时运行
L4 desire/patience：未进入 L5
L5 handoff：首次 /context 1.5s 超时曾丢失
```

这些不是“L2 与 L5 重复”，而是 **L5 还没把 L0/L4 的输入完整接上**。

## 最终规则

```text
1. L2 只存原文，不直接进 prompt
2. L3 只提供事件卡
3. L4 只提供自然语言，不上浮数值
4. L5 只做本次唤醒组装，不创建记忆
5. L6 只表达，不拥有人格/记忆真相
6. 旧 L2 编号正式退役，统一叫 L5
```
